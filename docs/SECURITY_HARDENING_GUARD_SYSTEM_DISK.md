# System Disk Guard — 默认开启

## 问题与兼容性

基线 `fe03d54` 的 YAML 加载器在 `guard_system_disk` 缺失时返回 `False`，仓库示例也没有设置该字段。独立数据盘未挂载时，挂载点目录可能仍可访问，旧配置可能在系统根文件系统上创建暂存、公开文件和同步记录。目录存在、可写和空间充足都不能证明数据盘已挂载。

现在 `PoolConfig` 和 YAML 加载器的默认值均为 `True`。`config/config.example.yaml` 是仓库中部署脚本会安装的备用生产模板，已显式写入 `guard_system_disk: true`。CLI 默认读取 `/etc/pool-poc/config.yaml`，也可用 `--config` 指定；无环境变量开关。`POOL_POC_ASSETS` 仅覆盖资产清单位置。

| 配置值 | 升级后行为 |
| --- | --- |
| 省略字段 | 开启保护（有意改变旧行为） |
| `true` | 开启保护 |
| `false` | 明确关闭；仅用于隔离的单盘开发或特殊环境，不推荐生产使用 |
| `null`、字符串、数字、容器等非 YAML 布尔值 | 配置错误，CLI 返回 `2`，不回退到关闭 |

## 检查与拒绝

1. `sync` 先检查授权、来源和目标路径。护栏解析路径，比较系统根（Debian 的 `/`；Windows 由操作系统查询）与公开存储根、实际目标父目录、暂存目录、同步审计目录的文件系统设备号 `st_dev`。若目标目录不存在，从解析后的路径向上寻找最近存在的目录，不创建目录做探测。暂存目录解析后仍须在公开树之外。
2. 发现写入位置落在系统根文件系统、无法解析目录或不能可靠探测设备时，退出 `1`、向 stderr 报告，不启动下载，不创建暂存或公开文件。空间余量仍在下载前检查。护栏拒绝不写 JSONL：数据盘丢失时，审计目录也可能退回系统盘。其他同步事件在审计位置通过检查时仍使用原 JSONL 格式。
3. `publish` 在写目标前重新解析并检查，防止直接沿用下载前的设备判断。若检查在下载后拒绝，已创建的暂存文件由同步流程清理。原子替换和哈希检查仍在原有流程内，跨设备分支以实际目标父目录判断设备。

护栏不识别特定 UUID，也不能锁定挂载或消除检查与写入之间的竞态。部署侧仍应约束数据盘挂载依赖及卸载后的目录权限；不应把 `st_dev` 检查当成挂载管理。此变更只针对同步写入，`verify`、`check-upstream` 和 `remove` 的命令行为未改。

## 迁移与回滚

- **`PRODUCTION_CONFIG: UNKNOWN`**：没有经确认的可用只读生产会话，本次未连接生产。线上是否已显式开启，以及是否已运行此提交，均未核实。
- 人工部署前核对生产配置来源、数据盘与各实际写入目录。缺字段的旧配置升级后自动开启；建议人工显式写 `guard_system_disk: true`。若已有 `false`，升级不会覆盖，应人工确认并改为 `true`。不要用示例覆盖资产清单或生产配置。
- 如升级后拒绝同步，优先核对挂载、路径解析和审计落点。单盘开发可在独立测试配置显式设 `false`。生产若必须回退应用版本，先暂停同步，保留现有配置与数据，并确认回退版本的配置显式为 `true`；旧版本即使显式开启也没有本修复的全路径与失败关闭检查。不要用关闭护栏代替修复挂载。
