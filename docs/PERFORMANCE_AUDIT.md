# Pool V0.2 性能审计 · V0.1

**决策：保持生产配置。** 已定位的成本在客户端可观测：移动小文件冷连接约四成时间花在首字节之前；在本次独立测点，同一 TLS 连接的后续请求通常快于首件，且 Node 的 HTTP/2 接收窗口实质影响了下载时间。没有证据把问题归咎于 Nginx worker、磁盘或 300 Mbps 端口。详见[分组数据与复现](PERFORMANCE_BASELINE.md)及[五项实验、验收和回退](OPTIMIZATION_ROADMAP.md)。

## 边界与证据

读审 `pool/`、`tests/`、`config/`、`scripts/` 的源码/部署/测试脚本、依赖、README、原部署和验收文档及现存测速报告。公网探针仅访问已批准的合成 JPEG，验证证书；未运行部署、同步、全套公网验收或服务端压测，未改任何生产配置、系统参数、DNS、资产和授权。香港 Debian 12、4C4G E5-2686 v4、300 Mbps、系统/数据盘 30/50 GB 为给定规格。未取得运行节点 `nginx -T/-V`、内核或计数器快照：模板代表意图，响应代表外部行为，历史快照不是当前状态。

- **热路径：** 公网 80 提供 ACME/重定向；443 的 `root /srv/pool/data`、`try_files $uri =404` 直接服务文件，GET/HEAD 及拒绝规则保留；没有经过 127.0.0.1:8080、Python 或 GitHub。见[443 模板](../scripts/nginx-pool-public-https.conf.template)、[部署渲染](../scripts/deploy.sh#L58-L94)。无理由引入 proxy_cache。
- **入库路径：**[同步 CLI](../pool/cli.py) 单资产授权校验、下载到 staging、读回验证、发布；[下载器](../pool/downloader.py) 与[存储](../pool/storage.py)的块读取和跨盘复制可影响入库时长/磁盘争用，不应把同步速度写成公网交付速度。上游 probe 读取首块后计时，不等价于 curl 的首字节。功能测试不提供并发容量曲线。
- **量具缺陷：**[Windows 采样器](../scripts/china-speedtest.ps1#L100-L129) 记录累计值且每轮新进程；[Shell 版](../scripts/china-speedtest.sh#L110-L136) 去掉前导逗号后又在 Python 用 `rounds[1:]`，可能吞掉首个 `{` 后静默写空轮次；DNS 数组构造也需用真实多 A 测例验证。汇总的 TESTED 不足为证。[公网验收](../scripts/public-acceptance.sh#L77-L84)的并发段打印状态而不逐件断言。后续基线须用固定输入离线检查 N 次尝试恰有 N 条记录（含失败）、错误不计成功、不会覆盖同日旧数据；旧 JSON 原样保留，另发带版本输出，失败可切回旧格式。日志 `rt=$request_time` 是整请求时间，不是服务端算力耗时；`bytes_sent` 含响应头，不是静态正文。

## 可计算的模型

冷请求 `T = D + C + H + Q + X`：解析、TCP、TLS、握手后至首字节、首字节后传输。移动第 1 轮为 **4.8 + 60.7 + 63.7 + 104.2 + 285.2 = 518.6 ms**。理想的 300 Mbps 下，仅发送 1,778,514 B 就需 47.4 ms；不能用端口速率反算完整请求延迟。相同对象、相同连接的连续访问才有机会摊薄 D/C/H；操作系统 DNS 缓存、TLS 恢复、TCP 连接复用、HTTP 对象缓存、服务端页缓存是五件不同的事。

单流量级可用 `min(路径可用带宽, cwnd/RTT, rwnd/RTT, 应用流控窗口/反馈时延, 处理与读取速率)` 理解，各项须统一为 B/s。用历史 ICMP RTT 49.2 ms 作近似，300 Mbps 的带宽时延积约 **1.85 MB**，大于测试对象；137 Mbps 对应约 0.84 MB。若仅为示意取初始窗口 10×1460 B，连续无损理想翻倍，约 7 次翻倍才到 1.85 MB。真实 IW、ACK、拥塞控制、重传、出网整形及闲置后窗口未测；不能据此宣布慢启动占用了具体毫秒。分辨方法：同对象同协议冷/复用交叉，对齐服务端 `ss -ti` 的 RTT/cwnd/retrans/拥塞算法与网卡计数，配对热读/自然未热读；不在生产清页缓存。大文件与多次小文件拆表。

## 协议、缓存与读取决策

|项目|可证实|未证实 / 决策|
|---|---|---|
|TLS、Keep-Alive|模板 TLS1.2/1.3，共享会话缓存 10m、有效期 1d；实测 TLS1.3、同 socket 六次 GET、新 TCP 恢复会话成功|票据复用与活连接复用不同。未测线上恢复率、空闲超时；同源短间隔受益不意味着要增加 timeout。|
|H1 vs H2|同一 Node ABBA 三件批次 H1 0.72–0.74 s，默认 H2 4.88–5.08 s；控制 H2 接收窗口后同协议两件批次也有明显差别|65,535 B / 49 ms 约 10.7 Mbps（仅量级）；不要把某一客户端的流控归因为服务器或 H2 固有劣势。下一轮同客户端、同总字节加 1/4 并行流对照，记录协商、首件和末件时间，不混入串行表。|
|H3 / QUIC|仓库模板未配置 QUIC 监听或 Alt-Svc，本轮没有 H3 基准|REJECT 直接上线。仅当跨网高丢包/多对象尾延迟重复出现，才在独立可回退测试域的 HTTPS 模板副本验证：相同样本/RTT/丢包条件及客户端，H2 对 H3 冷、热各自分组；UDP 可达率、回退总时、p95、CPU 秒/GiB 均记录。拟议门槛 p95 改善 ≥15%、无新增失败、CPU/GiB 增幅 ≤10%；代价为 UDP 运维及缓存广告残留，停止试验、撤测试广告并保留 H2 回退，不向生产发布 Alt-Svc。|
|ETag、Range、缓存|实测 304 无正文、两段 206 可校验拼接，保持 3600 s 缓存、no-transform|验证器不是哈希。`always` 可能使 404 也带一小时缓存，新发布或撤回有可见性延迟；不拉长 TTL。替换/撤回/陈旧 If-Range 的负例只在副本测试。|
|sendfile、AIO、文件系统|HTTPS 模板不显式设置 sendfile/aio/directio；有效值可来自全局继承。热小文件很可能由页缓存服务，但未测命中率|用户态 TLS 与 kTLS 发送路径不同；仅在 HTTPS 热路径 CPU 饱和时比较 sendfile。Linux 原生 AIO/directio 有对齐限制，绕开缓存会伤害重复小图和非对齐 Range；线程池只能缓解阻塞读，不会提高物理带宽。无冷读瓶颈前拒绝改 AIO、预读、挂载参数或 open_file_cache（还需验证撤回时旧描述符）。|

## 服务端取证：尚待管理员提供，不作为已测值

在低流量基线与获批实验窗口各取相同长度（例如 60 s），记录时区、对象、并发、是否同步入库。以下均为只读观察；不安装缺失工具，不公开完整配置或用户 IP。

|可能瓶颈|最低证据集|如何判断|
|---|---|---|
|CPU / TLS / 虚拟化|`nginx -V`；本机私下核对 `nginx -T` 的 http/server/location 继承值和有效站点；`mpstat -P ALL 1 60`、`pidstat -u -C nginx 1 60`|核对单核满载、steal、worker CPU 秒/GiB；同一时刻网口/磁盘未饱和才能隔离 CPU。load 0.00 不等于无限余量。|
|内存 / 页缓存|`free -m`、`vmstat 1 60`、`/proc/pressure/memory`；留意 swap-in/out、major faults|4 GB 含页缓存；低 free 本身不是瓶颈。观察 RSS、可用内存、压力与请求尾延迟是否同变。|
|磁盘读取|`findmnt -T /srv/pool/data`、`df -h`、`iostat -xz 1 60`；热重复 vs 获批的不同合成文件集|容量占用率不是 IOPS/带宽。比较 await、队深、实际读 B、iowait；排除同步器同时读写。区分已热与自然冷，首次访问并不保证物理读。|
|网络 / 并发|`ip -s link` 前后差、`sar -n DEV,TCP,ETCP 1 60`、`ss -ti`、已有访问日志按时窗统计 bytes/status/rt|在有效载荷趋于平台时看出口是否持续接近额度、是否重传、是否客户端窗口限制。10 并发成功不等价于 FD 耗尽或容量上限。观测到排队/丢弃再查 fd 限额，拒绝先扩大 worker_connections 或打开 BBR。|

服务器同窗数据缺失，不从历史 359 MiB RAM、数据盘约 1% 或 10 次并发反推余量。两台香港节点若各自都有独立 300 Mbps 出口、客户端分布足够均衡，理想聚合上界才接近 600 Mbps；共享上联、相同回程、单一长连接或热点不均都会折损。第二节点优先解决线路差异/故障隔离，不是把单用户速率翻倍；具体上线门槛含撤权一致性见[路线图 P2](OPTIMIZATION_ROADMAP.md)。

**变更纪律：** 任何候选只先改隔离副本；试验前封存原文件、启用链接及有效配置，逐变量比较并复验完整性、授权和内部监听；回退恢复原 Pool 专属文件和链接、语法校验后再按批准流程 reload。不要重跑整个部署脚本来回滚，它可能重装示例配置，失败分支也不会恢复旧公网文件。本阶段无生产变更需回滚。
