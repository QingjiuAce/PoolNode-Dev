# V0.3 文件系统加固报告

基线 `62b0cb8`，分支 `fix/guard-system-disk-race-hardening`。生产配置仍为 **UNKNOWN**，未连接或部署生产。

| 问题 | 实现与结果 |
| --- | --- |
| F1 跨文件系统 | 保护开启时仅允许同设备发布：核对暂存 FD、公开根与目标父目录；无跨盘复制分支。失败时不替换旧目标。显式 `false` 保留兼容复制。 |
| F2 暂存竞态 | POSIX 的目录创建和独占文件打开在已核验目录 FD 下执行。下载、格式检查、流式 SHA256 共用通过 `fstat` 的文件对象，不按路径重开。失败只按身份清理；不能安全清理则报告。 |
| F3 审计 | `sync` / `remove` 共用安全审计入口，实际打开文件后校验设备、类型及身份。删除前打开并再次核对审计目标；删除已发生、日志未完成时非零退出并报告，不承诺回滚。`verify` / `check-upstream` 原本无审计写入，保持只读。 |
| F4 低余量 | 低余量仍拒绝，可向通过护栏的审计文件写 `rejected`；底层设备不可信则不写；审计异常与原拒绝原因分别报告。 |
| F5 文件系统错误 | 发布的预期 `OSError` 包装为保留 errno 和异常链的业务错误，输出不含底层绝对路径；替换后核验失败与替换前失败区分。 |

## 残余边界与部署条件

POSIX 上目录 FD 阻止挂载消失后向系统根回落。延迟卸载可以让已持有的对象继续指向分离卷；可见性核验能发现观察到的变化，但无法原子保证命令返回后一刻仍可见。权限和身份检查不用于防御可在受信目录中并发改名、换挂或修改文件的特权主体。Windows 没有等价的标准库目录 FD 操作；文件正文依旧用设备已核验的描述符，目录创建、重命名和元数据操作仍存在路径竞态。没有引入 mount ID、openat2 或新依赖。

正常下载仍流式读写，新增检查集中在打开、发布、审计等边界，审计增加一次 fsync；未做吞吐基准。未修改授权、哈希规则、Nginx 或部署脚本。原有 115 项保留，修改前 114 通过、1 跳过。修改后 132 项：131 通过、1 跳过、0 失败（Windows 上既有符号链接用例跳过）。独立 Debian 12 实测 **NOT RUN**；本次可交独立复审，不能据此宣布生产可发布。

建议正式采用操作系统侧第二道防线：仅在确认**底层目录未被挂载覆盖**时，让挂载点由 root 所有且对运行用户不可写（如 `0555`），底层不要残留可写子目录。挂载卷自身保留原业务权限；非 root 运行 Pool。若由 systemd 管理同步作业，可评估 `RequiresMountsFor=/srv/pool` 结合挂载点条件与卷身份验证；本仓库没有现成同步服务单元，不将启动依赖当作运行时保护。不得在线直接修改已挂载的目录权限。迁移及恢复见[回滚说明](<SECURITY_HARDENING_V03_ROLLBACK.md>)。[演练报告](<DEBIAN12_MOUNT_GUARD_TEST_REPORT.md>)列出上线前证据。
