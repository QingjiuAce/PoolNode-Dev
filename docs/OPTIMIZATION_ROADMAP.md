# Pool 优化路线图：先校准单流，再决定改什么

本文是实验计划，不是部署记录。首五项按执行顺序排列：P0 先校准量具，P1 在现有单节点验证；P2 仅指另行立项的双香港节点。REJECT 表示本轮不进入实验。以下百分比均为**决策门槛**，不是预测收益。

## 基线与比较口径

- [移动原始三轮](../reports/network-tests/2026-11-21/china-mobile.json)来自同一早间窗口，每次 1,778,514 B、HTTP 200、同一 SHA256；总耗时 0.519–0.537 s，首字节 0.227–0.242 s，约 26.9 Mbps。JSON 记录的是系统存在代理、curl 绕过；不应写成系统无代理。[其他运营商与晚高峰](NETWORK_TESTING.md)仍是 **NOT TESTED**。
- [V0.2 报告 §4.2](V02_TEST_REPORT.md)将“137 Mbps”和“3.2–3.4 MB/s 单连接”列在同一行；按十进制后者仅为 25.6–27.2 Mbps。缺少对应六次请求的原始墙钟和连接记录，不能据此断言稳态速度。10 并发是聚合量；300 Mbps 是端口标称上限；香港到 Raw 是回源。三者都不是大陆用户单流速度。
- 后续只用已批准的自生成样本。固定客户端、接入方式、文件大小、SHA256、时段、HTTP 版本及缓存状态，每次只换一个变量；先后顺序交替，失败与超时入分母。吞吐一律按实际正文 B × 8 / 墙钟秒 / 10⁶；并发批次用首发至末次完成的墙钟，不把每流速度相加。curl 时间均从请求开始累计；冷连接 TLS 阶段用 `time_appconnect − time_connect`，不可把累计值当阶段时长。
- 涉及服务端的试验只在获批的隔离副本上做；保持 GET/HEAD、Range、404、证书校验与 SHA256 语义。若拟推广，先备份 Pool 专属配置、检查 Nginx 语法并复验[原有验收项](V02_TEST_REPORT.md)；任一正确性失败即停止，不用吞吐抵销。不碰原站、Raw、其他 vhost 或未经授权的图片。

## 1 · P0 — 补齐分层基线，复核计时分母

- **问题与证据：****冷建连有成本，仪器却混淆了累计值与阶段值。**[采样器的格式与映射](../scripts/china-speedtest.ps1#L100-L125)将 `time_appconnect` 记作 `tls_s`；三轮从发起到 TLS 就绪为 125–137 ms，而纯 TLS 段仅 61–65 ms，占总耗时约 12%。此外，汇总程序取首轮状态且 DNS 栏固定显示 `ok`，并不代表每轮通过。现有移动三轮能复算，但[汇总](../reports/network-tests/2026-11-21/summary.md)未覆盖联通、电信、广电或晚高峰，也不能解释 137 Mbps 的来源。
- **测试与机制：**用同一 JPEG，按运营商 × 空闲/北京时间 20:00–23:00 分组，至少跨两天，每格每天至少三次独立冷连接；另列六次串行复用批次，留存总字节、批次墙钟及新建连接数，不与冷连接混算。记录时间、接入方式、代理路径、HTTP 版本、状态、字节、哈希、分阶段时间、失败数。分层才能区别时段波动与配置效果。
- **位置：**[Windows 采样器](../scripts/china-speedtest.ps1)、[Shell 采样器](../scripts/china-speedtest.sh)与 `reports/network-tests/<日期>/`；按时段、批次另存，避免同运营商覆盖。
- **副作用与回滚：**占用测试者带宽，报告可能含地址；预留流量配额、对外仅给脱敏统计。停止采样即可，不改节点。
- **验收：**移动、联通、电信六格各有 ≥6 次尝试，广电可用时同测；缺格保留 NOT TESTED，不宣称全网结论。所有成功样本哈希正确，公布各格成功数/尝试数、中位数、范围；批次吞吐可由原始分子分母复算（舍入误差 ≤1%），否则保留“未证实”。

## 2 · P1 — 把连接复用与多流并发分开

- **问题与证据：**冷连接 TTFB 已占小文件总耗时约四成。[HTTPS 模板](../scripts/nginx-pool-public-https.conf.template)已启用 HTTP/2、TLS 会话缓存；不能把“打开 HTTP/2”当作新优化。
- **测试与机制：**同一线路、同一协商协议，A 连续六次各建新连接，B 同一连接串行六次；都实际读取六份完整正文，关闭客户端对象缓存。交替做 ≥10 对，记录每请求的新连接数、首字节、六次总墙钟与字节。复用可能省去后五次 TCP/TLS 往返；不证明首张图变快。
- **位置：**[网络测试指引](NETWORK_TESTING.md)的客户端连续下载场景；仅比较客户端调用方式，不改 Nginx。
- **副作用与回滚：**复用只利于同源连续请求，服务端断连会破坏试验条件；记录而非删去失败，恢复每次独立连接即可。
- **验收：**B 每批仅一次新连接且六次均 200、哈希正确，批次中位墙钟比 A 降 ≥15%，第二至六次的 TTFB 中位数下降；未达到则不建议调整客户端默认行为。

## 3 · P1 — 对重复下载使用条件请求，而不是延长缓存期

- **问题与证据：**[公网验收](V02_TEST_REPORT.md)确认有 ETag 与 Last-Modified，但有头不等于客户端利用它们。[公网模板](../scripts/nginx-pool-public-https.conf.template)已设 `max-age=3600, no-transform`，且 `always` 也覆盖错误响应。
- **测试与机制：**模拟已有缓存但需重验证的用户；A 无条件 GET，B 发缓存中的 ETag（If-None-Match）。未修改、已替换、已撤下三种状态各跑 10 对；替换样本固定为不同内容且另测同大小/同修改时间的情况。B 应只在内容未变时返回 304，省下正文，不省去网络往返。
- **位置：**客户端测试流程及[隔离静态 vhost](../scripts/nginx-pool.conf.template)；用临时合成资产模拟替换和撤下，不动生产资产。
- **副作用与回滚：**基于元数据的验证器可能碰撞；已新鲜的缓存也不会立即感知撤下。错误 304 或错误响应被当成成功即停试；回退无条件 GET、丢弃试验缓存。不要延长 TTL、不要把 ETag 当内容哈希。
- **验收：**未修改组 10/10 为 304、零正文字节且本地缓存哈希正确；替换组 10/10 为 200 且新哈希正确，撤下组 10/10 为 404。任何碰撞都阻止对可变路径推广。

## 4 · P1 — 验证单流断点续传是否值得保留临时文件

- **问题与证据：**[验收报告 §3](V02_TEST_REPORT.md)验证首段 1024 B 的 206，并未给出中断后完整恢复的成本或拼接完整性。
- **测试与机制：**同一 JPEG 在收到一半时受控中断；A 重下全件，B 用已收长度、Range 和 If-Range 请求余段。固定连接方式，每组 10 对，记录两次请求合计的正文 B、最终完成时间和 SHA256；另测中途替换文件，若返回 200 必须丢弃旧片段。节约的是重复字节，不是加速无中断的首次下载。
- **位置：**客户端测试脚本、[静态服务原生 Range](../scripts/nginx-pool-public-https.conf.template)；仅客户端临时目录留片段，不改上游同步器。
- **副作用与回滚：**临时文件占空间，误拼会损坏原图；无法确认强验证器、偏移、Content-Range 或总长时放弃续传，删除客户端片段，退回完整下载。
- **验收：**未变组 10/10 拼接哈希匹配，较重下组每件合计正文至少少 30%；替换组无一误拼。完整性不能确认则不发布自动续传建议。

## 5 · P1 — 对高 RTT 的 HTTP/2 客户端验证接收窗口

- **问题与证据：**[本轮基线 C](PERFORMANCE_BASELINE.md) 中，Node H2 两件批次，65,535 B 窗口为 3.092/3.167 s，1 MiB 为 0.749/0.920 s。在这个客户端比改服务端文件读取更值得先测；尚无浏览器用户占比或受影响比例。
- **实验与机制：**在 `docs/NETWORK_TESTING.md` 对应的客户端流程中增设独立 Node 基准；同一 JPEG、单连接、相同 SHA，将 stream/connection 接收窗口分别做 2×2 A/B，再用实际下载客户端复核；三网高低峰分层，交错 ≥10 对。窗口约束在途字节，增加窗口可能减少等待 WINDOW_UPDATE 的时间。
- **副作用与回滚：**多流同时下载会增加内存压力；记录 RSS 与并发流数。仅调整客户端实验会话；恢复默认、关闭临时会话即可。不关闭生产 H2。
- **验收：**目标客户端同类高 RTT 档批次时间中位数下降 ≥20%、RSS 增长 ≤10%、无新增错误且哈希全部一致；默认浏览器若无同类问题，不为它推广。

### 低优先备选 · P1（有条件） — 仅在本机静态发送出现 CPU 瓶颈时评估 sendfile

- **问题与证据：**[验收时点](V02_TEST_REPORT.md)十并发全部成功、load 0.00；这不是连续 CPU 剖面。三个模板没有给出有效全局 `sendfile` 值，不能据此推断它已关闭，当前也没有磁盘瓶颈证据。
- **测试与机制：**先只读核对生效配置、每 GiB 正文的 worker CPU 秒与磁盘等待。若未开启且 CPU 成为限制，在隔离静态 vhost 比较 A 当前值和 B `sendfile on`；固定热页缓存、相同合成数据与并发 1/5/10，每档交替 ≥10 批，统计 CPU 秒/GiB、吞吐与 p95 完成时间。减少用户态复制可能降低 CPU，但 TLS 路径未必受益；回环明文结果不能外推到公网 TLS。
- **位置：**同版本 Nginx 的[HTTPS 模板](../scripts/nginx-pool-public-https.conf.template)隔离副本；不改全局 `nginx.conf`，不改仅负责 ACME/301 的 [HTTP 模板](../scripts/nginx-pool-public-http.conf.template)。
- **副作用与回滚：**压测会占满 CPU 或 IO，影响同机服务；只用隔离机，出现错误立即停止，恢复副本旧配置并校验语法。
- **验收：**若原值已开或无 CPU 瓶颈，记录“不适用”并结束。否则仅当 HTTPS 十并发 CPU 秒/GiB 降 ≥15%、各档 p95 不恶化超过 5%、哈希与 Range 全通过才提议变更。

首五项的客户端落点：第 1 项修订 `scripts/china-speedtest.ps1` 的 `$fmt`、`$map`、汇总分支及 `scripts/china-speedtest.sh` 的对应输出；第 2 项在这两个采样器增加可选的单进程批次模式；第 3、4 项在 `scripts/public-acceptance.sh` 增加仅对隔离夹具运行的条件 GET 与续传用例；第 5 项记录 Node 客户端的 H2 实验设置；备选 sendfile 仅在 `scripts/nginx-pool-public-https.conf.template` 的隔离副本里改变一个指令。均为拟议位置，非已实施改动。

## 6 · P2 — 双香港节点（备选，不计入首五项）

- **问题与证据：**单节点可能对不同运营商有不同回程，也可能在热点时段出现容量限制；已有移动早间样本和单次十并发均不能证明需要第二节点。仅在 P0 跨日显示可重复的分线路退化，或生产监控出现持续出口饱和后申请预算。
- **测试与机制：**使用两台不同回程的获批香港测试节点 A/B；固定测试域名、证书、数据及客户端，测试客户端指定目标地址，不改生产 DNS。至少三网、两个时段、两天，每格交替 ≥10 对，分开记录单流耗时、路由、错误率、节点出口；容量另测相同总并发下 A 单机与 A/B 平分负载的批次吞吐。单流不叠加两机带宽。两机使用同一授权清单版本，校验字节与 SHA256 后才允许分流；模拟撤权及 B 离线再上线，版本落后的节点必须隔离而非重新接流。
- **位置：**两节点的 `/etc/pool-poc/assets.yaml`、`/srv/pool/data` 和 `/etc/nginx/sites-available/pool-public.conf`；逐节点核对[删除流程](../scripts/remove-asset.sh)与[公网验收](../scripts/public-acceptance.sh)，对照[公网部署](PUBLIC_DEPLOYMENT.md)。
- **副作用与回滚：**新增带宽/存储费用、双份证书运维及撤权不同步风险。先摘除 B 的测试分流，恢复仅 A；关闭 B 的公网入口并核对两端撤权状态，不能只撤 DNS（解析缓存仍可能命中 B）。不删除 A 数据，不改原站地址。
- **验收：**最差运营商格子的配对下载耗时中位数下降 ≥20%，或相同负载预算下聚合吞吐提高 ≥25%；其他格子中位耗时不退化 >5%。额外费用须获批；两节点哈希 100% 正确、撤权确认前未完成同步的入口均停流；确认后两节点立即 404、离线节点恢复无旧资产重现。任一一致性门槛失败，即使容量达标也不推广。

## REJECT · 本轮不做

不为跑满 300 Mbps 默认并发分片；它会放大请求数，且聚合速度不能代表单流。不给 JPEG/PNG 重新编码或开启全站动态压缩；原图要求字节一致，目前没有压缩收益证据。不引入 CDN、反代、长时 immutable 缓存或改系统拥塞控制：跨节点撤回、可变 URL 或整机影响超出这轮验证。先拿到可复算的分运营商数据，再单独立项。所有回退只撤试验变量；[公网回滚手册](ROLLBACK.md)不是日常调参步骤。
