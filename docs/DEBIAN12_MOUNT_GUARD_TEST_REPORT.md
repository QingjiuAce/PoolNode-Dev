# Debian 12 挂载故障验证

**NOT RUN。** 当前是 Windows，未发现 WSL 发行版或 Docker/Podman，也没有获准使用的独立 Debian 主机。不安装虚拟化软件，不使用生产服务器、数据盘或挂载点。Windows pytest 使用真实临时文件和描述符、模拟设备边界，不能代替实际挂载演练。

## 待执行方案

在一次性 Debian 12 VM 中创建私有传播的 mount namespace、每场景独立的临时挂载目录和 ext4 loop 镜像。创建非特权 Pool 测试用户；挂载控制与业务进程分离。数据只用合成 PNG 与本地限速服务。每个子场景前记录底层目录内容、挂载设备、权限和配置；结束后只清理该场景设备和目录。普通卸载可能因 FD 忙而被拒绝，不要把 `EBUSY` 当成已卸载。

| 场景 | 核对项 |
| --- | --- |
| A / B / C：正常、未挂载、普通卸载 | 正常时文件、SHA256、审计一致；卸载后执行新命令应非零退出，底层目录无新增业务文件。 |
| D / E / H：下载中、发布前、延迟卸载 | 按下载和发布阶段收集状态；确认已打开对象不回落，公开路径失效时不报完整成功，分离卷可检查清理。 |
| F：暂存与目标分盘 | 保护模式拒绝，旧公开文件摘要不变，无隐藏跨盘副本。 |
| G / J：审计失挂载或只读 | `sync` 不回退日志；`remove` 在审计不安全时保留资产；`verify` 与 `check-upstream` 不写日志。记录原始错误与审计错误。 |
| I：底层目录权限 | 确认未挂载后将**测试**底层目录设为 root 所有且对业务用户不可写；挂载时验证数据卷权限正常，卸载时验证原目录仍不可写且没有业务子目录。 |

以退出码、stderr、旧/新文件摘要、暂存与 JSONL 落点、底层目录差异为验收证据。真实演练通过前，不将模拟结果当作系统盘零写入的生产证明。
