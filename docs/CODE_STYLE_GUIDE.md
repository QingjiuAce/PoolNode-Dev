# Pool 维护风格

## Python

- 模块、函数、变量用 `snake_case`，类用 `PascalCase`，常量用 `UPPER_SNAKE_CASE`，模块私有成员以 `_` 开头。稳定接口不为命名偏好而改名。用含义明确的变量区分文件路径、已写字节、总读取字节和官方/本地哈希。
- 按标准库、第三方、本地模块组织导入；按 PEP 8 保持空行与缩进。不为本项目引入新的格式化或类型工具链。
- 公共入口优先标注参数、返回值；值结构稳定时用现有 dataclass 或轻量的字典类型。边界解析数据仍按现有运行时规则处理。保持 Debian 12 的 Python 3.11 兼容。
- Docstring 首句说明职责，必要时另段说明重要输入、返回、异常及副作用。短函数不硬凑章节；注释解释为何保留授权顺序、独立路径检查、回环测试例外、大小双检及清理，而不是重述代码。

## Bash 与 PowerShell

- 用能区分请求、计时结果和报告记录的名字；保持已发布参数、默认值及 JSON 字段/类型。Bash 引用路径及变量，维护管道退出状态时检查子命令；空集合和空结果分别处理。编辑后对所有脚本执行 `bash -n`，有 ShellCheck 时再作补充。
- PowerShell 支持 Windows PowerShell 5.1，不引入仅 7.x 支持的语法；带非 ASCII 内容的现有脚本保留 UTF-8 BOM。零时间与空值不是同一含义。对测速代码说明 curl 累计里程碑与换算口径，不把它们理解为各段独立耗时。用 5.1 Parser 做语法检查，不能代替运行测试。
- Nginx 注释标出模板职责和指令作用域；没有读取有效配置时不推断继承行为。部署配置及缓存、TLS、读写策略单独审查，不混入注释改动。

## 错误和审计

- 保留异常类型、`reason` / `kind`、CLI 退出码、输出频道和 JSONL 字段。包装底层错误时用 `raise ... from ...`；`finally` 负责暂存资源清理。不要以宽泛捕获吞掉关键错误。
- CLI 是用户错误出口，避免同一错误多次打印；审计记录保留足够上下文，但不新增凭据、授权证据内容、带密钥 URL 或无关绝对路径。若既有输出需要脱敏，作为单独的兼容性变更审查。
- 先为已存在的行为补测试，再修改易变化的实现。报告区分已运行、静态验证、跳过与未测试，不把历史生产验收冒充本次验证。
