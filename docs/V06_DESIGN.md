# PoolNode v0.6 — 自适应传输调度设计（D3）

> 状态：**设计草案，待审查**（任务书 §14 第四步前不开始重构）
> 基线：v0.5（`range_transport.py` 动态队列 + 连接复用）
> 依据数据：81 轮三臂探针 / 189 项 SHA 校验 / 5 个劣化事件

## 1. 设计原则

1. **证据驱动**：所有阈值先由配对实验校准，再写入默认值；本文件中的数字均为**候选初值**
2. **不增加请求不增加风险**：新增逻辑只改变分块计划与并发阶梯，不复用绕过的校验路径
3. **可回退**：`--scheduler static` 永远保持 v0.4 语义；`auto` 失效时自动降级
4. **可观测**：每个决策（升档/降档/对冲/放弃）都写入 metrics 时间线
5. **资源有界**：并发 ≤32、对冲 ≤4、重试 ≤2/块、总请求数 ≤ 计划块数 + 对冲预算

## 2. 可用信号（不新增探测请求）

| 信号 | 来源 | 用途 |
|---|---|---|
| 单块字节数、耗时 | `_fetch` 按 64KiB 累计 `written`（新增） | 计算块速、检测慢块 |
| 已完成块中位耗时 | 块表 | 慢块判定基准（2.5×中位） |
| 聚合吞吐 A = 已完成字节×8/已用墙钟 | 下载器 | 估算剩余时间 T_rem |
| 有效并发数 | 块表 IN_PROGRESS 数 | 计算每流域速 |
| 块完成比例 | 块表 | 状态推进（TAIL/COMPLETE） |
| 探测/首波 ETag 与状态 | 既有 probe | 版本一致性（不重复探测） |
| 连接新建/复用计数 | `_TimedConnection` 既有 | 握手成本核算 |

> 不依赖系统时钟或"晚上八点"这类时间规律——时间规律是测量发现，不是客户端判据（任务书 TASK-2.2）。

## 3. 分块模型（TASK-2.1：解除 chunk 与 worker 耦合）

### 3.1 参数

| 参数 | 初值（候选） | 约束 |
|---|---|---|
| `C_MIN` | 96 KiB | 段小于此值时握手/慢启动占比反超收益（A1 106KB 实测有效下限附近） |
| `C_PREF` | 256 KiB | 健康窗的优选段长 |
| `C_MAX` | 1 MiB | 防止巨文件块数过少 |
| `N_MAX` | 32 | 单文件证据上限（27 轮 SHA 背书；64 段未测，不得默认启用） |
| `N_STATE` | 1 / 4 / 8 / 16 / 32 | 状态机给出的目标并发 |

### 3.2 计算

```
n_floor = ceil(S / C_MAX)          # 块不得大于 C_MAX
n_cap   = floor(S / C_MIN)         # 块不得小于 C_MIN
n       = clamp(N_STATE, n_floor, min(n_cap, N_MAX))
if n < workers + 1 and n < n_cap:  # 保证队列里有可偷的块
    n = min(workers + 1, n_cap)
块边界 = size*i//n（与 v0.4/v0.5 相同的整数除法，天然无缝无重叠）
```

### 3.3 示例（S=文件大小）

| 文件 | N_STATE=32 | 16 | 8 | 4 |
|---|---|---|---|---|
| 1.7 MB | 18 块 × 99KB | 16 × 111KB | 8 × 222KB | 4 × 445KB |
| 5.4 MB | 32 × 169KB | 16 × 338KB | 8 × 675KB | 4 × 1.35MB→C_MAX 修正为 6 × 900KB |
| 20 MiB | 32 × 640KB | 20 × 1MB | 20 × 1MB | 20 × 1MB |

> 与 v0.5 的关键差异：块数不再被 256KiB 硬性限制，5.4MB 在 N=32 时可达 32 流（169KB/块，仍在 96KiB 下限之上）。

### 3.4 边界与约束（C_MIN 的真实作用）

1. **C_MIN 决定块数上限**：`n_cap = floor(S / C_MIN)`。1.7 MiB 文件在 C_MIN=128KiB 时 `n_cap = 13`，
   因此 **w16 无法达到 16 流**（实际 13 块）；C_MIN=96KiB 时 `n_cap = 18`，w16 可达 16 块。
   这正是 TASK-C 要实测的差异，不允许用"理论可用并发数"代替测量。
2. **最后一块**：边界用 `size*i//n`，最后一块 = `[size*(n-1)//n, size-1]`，承接余数、可能比平均值略大，
   但不超过 `ceil(S/n)`；不需要特殊补块逻辑。
3. **文件小于 C_MIN**：`n_cap = 0` → `n = max(1, …) = 1` → 计划为单块，直接走整文件 GET
   （dynamic 路径在 `len(spans) < 2` 时已拒绝进入，回落到 single）。
4. **S 不能整除 n**：整数除法天然覆盖 `[0, S)`，无空洞、无重叠（既有性质测试锁定）。
5. **C_MAX 与 C_MIN 冲突**（S 很小但 C_MAX 也小）：`n_floor = ceil(S/C_MAX)` 可能大于 `n_cap`；
   此时以 `n_cap` 为准（宁可块小于 C_MAX 也不低于 C_MIN），并在 metrics 中记录 `plan_conflict`。

## 4. 调度状态机（TASK-2.3）

### 4.1 状态

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| INIT | 下载开始 | 校验参数，按文件大小定 N_STATE=4（<4MiB）或 8（≥4MiB） | 立即 → PLAN |
| PROBE | 计划就绪 | 首波（≥1 块完成或 400ms）收集聚合吞吐 A0、块速中位 m0 | 首波窗口结束 → 决策 |
| HEALTHY | T_rem ≤ 1.2s | **不升档**，自然完成（避免过度分段） | 完成 → TAIL/COMPLETE |
| DEGRADED | T_rem > 1.2s | **时间预算驱动的爬梯**（见 4.2） | 爬梯停止（收益不足/触顶/并行惩罚）→ RECOVERY 观察 |
| RECOVERY | 爬梯停止 | 保持当前 n，不再调整（下载内不降档，避免振荡） | 完成 → TAIL |
| TAIL | 剩余块 < 2×workers 或完成度 ≥85% | 停止升档；对慢块启用对冲（§5） | 全部块成功 → COMPLETE |
| COMPLETE | 全部块 SUCCEEDED 且 SHA 通过 | 原子发布 | — |
| FAILED | 任何块两次失败 / 校验失败 | 取消、清理、回退单流（既有语义） | — |

### 4.2 爬梯规则（核心：不做绝对阈值假设）

```
每波：n ← min(2n, N_MAX)，测量 A_k
gain_k = A_k / A_{k-1}
继续升档 iff  gain_k ≥ 1.25  且  T_rem > 1.2s  且  n < N_MAX
并行惩罚：若 gain_k < 0.7（加流反而变慢，如 11-23 12:05 现象）
          → 回退到 n_{k-1}，标记 parallel_penalty，停止升档
死区：0.7 ≤ gain_k < 1.25 → 保持当前 n，不升不降；连续 2 波死区 → 判为平台，停止升档
```

**Gain 的精确定义**：第 k 波（升档后到下一决策点之间）的
`A_k = 该波内已完成字节 × 8 ÷ 该波墙钟`（只统计该波内完成的块，不含探测请求）。
`A_0` 为首波（初始 n）的同口径值。gain 必须用**同一口径的波内字节/时间**，不得用累计吞吐
（累计值会被旧档位的块稀释，导致 gain 系统性偏小）。

**Gain 的最小可观察条件**：一波结束需满足 `已完成块数 ≥ 2` 或 `已完成字节 ≥ 计划字节的 25%`；
若 400ms 时仍不满足，延长到 800ms 上限；仍不满足则计为"无有效样本"——保持当前档位，
不产生 gain 判定（避免用单块噪声决策）。

- 依据：事件内 w16→w32 实测 ratio 1.29–1.91（中位 1.65）；健康窗 w32/w16 0.49–0.72（惩罚）
- `T_rem = 剩余字节×8 / A_current`；每次升档后重算
- **防抖**：两次升档间隔 ≥ 800ms；同一下载内最多 3 次升档（n0→8→16→32）
- **不降档**：下载内只升不降（RECOVERY 仅观察），避免振荡；跨下载由下次 INIT 重新开始

### 4.4 驻留时间与防抖细则

| 规则 | 值 | 目的 |
|---|---|---|
| PROBE 最短驻留 | 300ms | 避免首块噪声触发 |
| 升档最小间隔 | 800ms | 避免连续升档造成请求尖峰 |
| 同一下载升档次数 | ≤ 3 | 有界 |
| 状态切换总数 | ≤ 3（不含 COMPLETE/FAILED） | 稳定性验收 |
| 振荡定义 | 升档 →（gain<1 波）→ 再升档 | 计为一次振荡，验收要求 0 |
| 进入 TAIL | 一次性，不可退出 | 尾部只对冲不再升档 |
| 失败 | 立即 FAILED，跳过 TAIL | 安全退出 |

### 4.3 与任务书状态的映射

INIT/PROBE/HEALTHY/DEGRADED/RECOVERY/TAIL/COMPLETE/FAILED 均实现为显式枚举，写入 `metrics` 的 `kind:'states'` 时间线（新增），便于实验复盘。

## 5. 慢段对冲（TASK-2.4）

### 5.1 触发

- 仅在 `TAIL` 或 `DEGRADED` 状态
- 块 `elapsed > max(0.8s, 2.5 × 已完成块耗时中位)` 且 `T_rem > 1s`
- 每块最多 1 次对冲；全下载对冲预算 = `min(4, ceil(0.25×块数))`

### 5.2 机制（避免偏移写入冲突）

1. 对冲请求取该块**尚未写入的剩余区间** `[start+written, end]`（`written` 由 `_fetch` 按 64KiB 更新）
2. 响应写入**内存缓冲**（≤ C_MAX），逐项校验：状态 206 / 精确 Content-Range / 强 ETag 与探测一致 / 长度
3. 通过后获取块锁：若原块尚未完成，把缓冲写到 stage 的 `start+written`，标记 SUCCEEDED；否则丢弃缓冲
4. 尽力取消原请求（关闭其连接）；原请求若先完成，对冲结果作废
5. 失败的对冲计入 `hedges_failed`，**不**触发重试风暴（每块最多 1 次）

### 5.3 预算、缓冲区与提交锁（TASK-D 第 7 项）

| 项 | 定义 |
|---|---|
| 每块对冲次数 | ≤ 1 |
| 并发对冲上限 | `min(4, ceil(0.25 × 计划块数))` |
| 全下载对冲预算 | 与并发上限同值；不随升档扩大 |
| 缓冲区 | 每个对冲一个内存缓冲，长度 ≤ C_MAX（1 MiB）；总内存 ≤ 4 MiB |
| 提交锁 | 每块一把 `threading.Lock`；持有锁时再次检查 `state != SUCCEEDED`，满足才把缓冲写到 `start+written` |
| 写入原子性 | 缓冲写入一次 `write`（≤1 MiB，单次系统调用量级），写后更新 `written` 并标记 SUCCEEDED |
| 失败语义 | 对冲失败仅记 `hedges_failed`；不重试、不触发整体回退 |
| 与重试关系 | 重试只处理传输错误（每块 1 次）；对冲独立，不叠加 |
| Alpha 范围 | **不实现**，仅保留设计（任务书 TASK-D 要求） |

### 5.3 明确不做

- 不对所有块无差别复制
- 不对健康窗（HEALTHY）启用对冲
- 对冲与普通重试是两条独立路径（重试只处理传输错误，仍为每块 1 次）

## 6. 连接与探测优化

- 保留 v0.5 的 worker 私有 keep-alive（TTFB 285→55ms 实测）
- **探测合并**：由 worker 0 执行探测并复用其连接（省 1 次握手，约 120ms）
- 服务端关闭连接（`Connection: close` / keep-alive 超时）→ 安全重建（既有测试覆盖）

## 7. 参数与开关

| 开关 | 语义 |
|---|---|
| `--scheduler auto`（默认） | 状态机（本节全部逻辑） |
| `--scheduler dynamic` | v0.5 行为（固定 256KiB 块、cap 2×workers、无对冲） |
| `--scheduler static` | v0.4 行为（固定等分、每请求新连接） |
| `--workers 1..32` | 用户硬上限（auto 不得超越） |
| `--no-hedge` | 关闭对冲（实验对照/保守部署） |
| `--max-segments 32` | 段数硬上限 |

任何调度选择都不得绕过白名单、SHA、TLS、Range 校验与单流回退语义。

### 8.3 验收指标的精确定义（TASK-D 第 8 项）

| 指标 | 精确定义 | 门槛 |
|---|---|---|
| 健康窗退化 | 对每个健康配对组 `d = 1 − median(Auto) / median(Static)`；同时计算 P90 口径的 `d90` | `d ≤ 10%` 且 `d90 ≤ 15%` |
| 事件窗提升 | 对每个事件配对组 `g = median(Auto) / median(Static) − 1`；同时记录最差组 | `median(g) ≥ 30%` 且 ≥4/5 组 `g > 0` |
| 稳定性 | ① 单次下载状态切换数 ≤ 3；② 振荡计数 = 升档 →（gain<1 的波）→ 再升档 的次数 | ① 全部满足；② 必须为 0 |
| 完整性 | SHA 通过率；故障注入通过率（T1–T5 + 对冲专项，Beta 起） | 100% |

> 口径统一：Auto/Static 使用同文件、同窗口、交替执行、≥5 组配对；不得跨窗口拼接。
> 所有指标同时附 P90 与最差值，禁止只报最佳。

## 10. 未决问题（需实验回答）

1. `C_MIN` 取 96KiB 还是 128KiB：取决于 1.7MB 在 32 段下的实测（本次探针用 169KB 段验证了 5.4MB，未测 96–128KB 段）
2. 爬梯波长的最优值（400ms/800ms）——过短被噪声触发，过长错过事件转换
3. 对冲的服务器侧放大效应（事件内 25% 预算是否会造成排队）
4. 12:05 现象是否可复现（决定 parallel_penalty 是否保留）
5. 64 段是否需要（事件内 w32 已达 7.7–38 Mbps，收益递减点未知）
