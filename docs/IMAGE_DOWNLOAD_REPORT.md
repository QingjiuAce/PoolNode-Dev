## 1. TL;DR

- **早高峰单流下载可达 27 Mbps（冷）/ 136 Mbps（连接复用稳态）**，线路本身档位不低；
- **晚高峰回程崩塌至 0.4–0.6 Mbps（单流）**，21:04 复测无恢复——瓶颈为**回程 PCCW BGP 的
  per-flow 晚高峰整形**（并发剂量实验 1→16 流线性扩展已实证，非聚合令牌桶）；
- **去程三网直连不受影响**：上传方向晚高峰 45.9 Mbps，与早间持平甚至略升；
- 服务端两台机器（Pool 300M 口 / CN2 盒子 10M 口）端口本身均不堵（同时刻 CF 上行
  189 Mbps / 港内拉满 10M 口），**瓶颈 100% 在"国际回程 → 大陆移动"段**；
- **已验证的解法排序**：客户端分段并发（免费、零服务端改动，16 流 ≈ 6.35 Mbps）>
  CN2 路线（2.3–2.9 Mbps）> EdgeOne 免费版（待实测）> CF 免费版（**已否决**）；
- jsDelivr 全变体（**已否决**）、Gcore 免费版（待实测）。

### 3.5 并发剂量-响应实验（21:08–21:25 · 决定性实验）

| 并发流数 | 聚合吞吐 | 单流均摊 | 相对单流 | SHA256 |
| --- | --- | --- | --- | --- |
| 1（基线 ×2）| 0.46–0.54 | 0.50 | 1× | ✅ |
| 2 | 1.12 | 0.56 | 2.2× | ✅ |
| 4 | 1.90 | 0.47 | 3.8× | ✅ |
| 8 | 3.60 | 0.45 | 7.2× | ✅ |
| 16 | **6.35** | 0.40 | **12.7×** | ✅ 16/16 |

**判定：per-flow 整形**（每条 TCP 流各自 ~0.5 Mbps，流间线性叠加，16 流无拐点）。
连接复用对照：晚高峰复用与冷连接无差异（0.47–0.53 Mbps）——瓶颈已从建连成本
转为回程链路本身。**"换路径"之外的客户端并发手段（复用/HTTP2/QUIC 单流）均无效，
唯有多流并发有效。**

## 4. 根因分析

1. **方向不对称**：去程三网直连（请求/上传快）vs 回程 PCCW BGP（下载晚高峰被整形）。
   用户感知的"下载慢"100% 落在回程国际段。
2. **整形方式为 per-flow**：并发线性可绕（16 流实证），未测到拐点（32/64 流待测）。
3. **两台服务器端口均健康**（同时刻 CF 上行 189 Mbps / 港内拉满 10M 口）——排除了
   服务器自身瓶颈，也排除了"整站被限"。
4. **晚高峰劣化深度大且持续**（20:30 → 21:04 无恢复），对 5.67MB 级原图：
   晚高峰单流下载 ≈ **2–10 分钟/张**，完全不可用；预览图（20–80KB）≈ 1–2 秒，可用。

## 7. 开放问题

1. 32/64 并发的饱和拐点（单流均摊 0.56→0.40 的缓降是否收敛）
2. EdgeOne 免费版对移动晚高峰的真实表现（理论 vs 实测）与"不计量"条款边界
3. BBR 在 per-flow 整形环境下的实际增益（整形丢包 vs 降速的实现细节未知）
4. sshd 主机密钥丢失根因（影响重启稳定性观察）
5. PCCW 回程是否可协商升级（E1）

## 8. 方法论与可复现说明

- 全部服务器端测试为临时端点（:8800/:8900 python http.server），**测后即拆**，未触碰
  生产配置与数据；第三方路线测试仅读取公开文件（dl.bszx.site 自有资产 / GitHub 公开
  仓库经公共 CDN），未保存任何未授权图片

  [OPTIMIZATION_ROADMAP](OPTIMIZATION_ROADMAP.md)）

  全网结论
