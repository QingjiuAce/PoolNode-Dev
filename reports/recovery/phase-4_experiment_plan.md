## 1. C_MIN 参数复验

### 1.1 目标

补齐 96 KiB 与 128 KiB 的**背靠背配对**数据，使 v0.6 的分块参数决策有依据。

### 1.2 档位与组数

| 档位 | 时间 | 组数 | 备注 |
|---|---|---:|---|
| 健康窗 | 12:15 | 5 | 同时作为"稳定健康窗"对照 |
| 事件窗 | 20:15 | 5 | 夜间高发窗起点 |
| 事件窗 | 21:15 | 5 | 高发窗中段 |
| （建议补） | 22:15 | 5 | 事件尾；若 21:15 样本已足够可省 |
| （建议补） | 23:15 | 5 | 事件尾；同上 |

任务书要求的最低计划是三档（12/20/21）。**是否补 22/23 由用户在启动前决定**；
本计划建议补齐五档，理由：历史数据显示劣化可持续到 23:00 之后（11-26 23:45 单流仍 0.05 MB/s），
只有两档事件窗不足以判断"事件尾是否回升"。

### 1.3 协议（不可更改）

- 每档 5 组；组内 96K/128K **背靠背**（中间不插入其他下载）；
- 组内 A/B 顺序随机、组间顺序打乱；
- 每臂记录：实际 spans、每块相对开始时间与耗时、活跃 worker 数、完整字节跨度核验、SHA；
- 原始 JSONL 只追加到 `reports/benchmarks/cmin-experiment/runs.jsonl`；
- 11-26 01:15 的旧顺序数据**不计入**配对分析（`slot_kind` 与 run_id 可区分）。

### 1.4 窗口分类（依据探针，不按钟点）

| 判据 | 分类 |
|---|---|
| 该档探针中位 ≥ 5 Mbps | 健康窗 |
| 该档探针中位 < 5 Mbps | 事件窗 |
| 事件窗后首个回升 ≥ 5 Mbps 的档位 | 事件尾 |
| 探针无数据 | 网络状态未知（保留原始记录，不并入统计） |

阈值 5 Mbps 来自历史分布（健康窗 20–60 Mbps，事件窗 0.1–2 Mbps），本计划先声明，
避免事后挑选口径。

### 1.5 预算

每档 ≈ 2 C_MIN × 4 臂 × 5 组 × 1.7 MB ≈ **68 MB**；五档 ≈ 340 MB。
晚高峰 0.1–0.7 MB/s 下每档 2–10 分钟，五个任务错峰（:15/:25/:35）不重叠。

## 2. v0.5 A/B/C 分块队列调查

### 2.1 臂定义（沿用 investigate 分支既有实现）

| 组 | 配置 |
|---|---|
| A | v0.4 static，16 等分块 |
| B | v0.5 dynamic，强制 16 块 |
| C | v0.5 dynamic，21 块 |

### 2.2 档位

20:35 / 21:35 / 22:35 / 23:35，每档按 `rc_matrix.py` 的 `--reps 5` 执行
（即每臂 5 组，三臂交错）。

### 2.3 必须记录的字段（脚本已具备，见 smoke 实测）

`telemetry.chunk_count / workers_used / chunks_done / requests_total /
first_chunk_end_ms / last_chunk_end_ms / max_queue_wait_ms / median_queue_wait_ms /
conn_new / conn_id`，外加 `assembly_ms` 与总 `wall_ms`。

### 2.4 要回答的问题（不得只用最大排队时间下结论）

1. C 组是否稳定出现第二波排队（`chunks_done > workers_used` 的比例）；
2. 第二波排队是否增加总耗时（控制网络条件，用同档 A 臂作参照）；
3. 排队是否降低最终吞吐（结合 `mbps` 与 `assembly_ms`）；
4. A/B/C 在同一档内是否稳定差异（5 组的中位数与离散度）；
5. 21 块是否适合 16 worker（`workers_used` 与 `requests_total` 关系）；
6. 是否需要调整生产 auto 计划（必须给出"不改"或"改什么"的明确结论）。

### 2.5 预算

每档 3 臂 × 5 组 × 5.4 MB ≈ **81 MB**；四档 ≈ 324 MB。

## 3. RC 配对（v0.4 static vs v0.5 auto）

### 3.1 门槛（**不降低**）

| 项 | 门槛 |

| 健康窗退化 | 中位 ≤10%，P90 ≤15% |
| 自然劣化窗收益 | 中位 ≥30%，且 ≥4/5 组为正 |

| 原始 metrics | 每次运行独立文件，不得覆盖 |

### 3.2 与历史的关系

- 11-25 的 130 条数据**缺 scheduler 字段**，不可用于验收（已勘误）；
- 11-26 的模拟劣化窗（netem）+2.31%、3/5 为正，**不能**替代自然拥塞窗；
- 本计划的 RC 数据必须来自**自然劣化窗**（20–23 点实测），并在报告中标注当日探针状态。

### 3.3 预算
